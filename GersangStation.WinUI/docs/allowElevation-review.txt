GersangStation allowElevation - 구현 점검 및 제출 설명 준비
점검일: 2026-10-31
기준: HEAD ec1639f 및 현재 작업 폴더
상태: 정션 전환 이전 구현의 내부 검토 초안. 현재 구현에 대한 제출 자료로 사용하지 말 것.

범위와 확인 방법
- 현재 작업 폴더의 소스 정적 검토 및 Microsoft 공식 문서 확인.
- 설치 CDN 일부에 HEAD 요청만 수행. 설치 파일 본문은 다운로드하지 않음.
- UAC 실행, 실제 설치/패치, 악성 경로 재현, IPC 공격, 전원 중단 시험은 수행하지 않음.
- 코드 변경 없음. 기존 SidebarView 변경은 점검 결과와 무관하며 그대로 보존.
- 외부 게임 Run.exe의 runas 실행은 사용자의 allowElevation 없는 환경에서 동작 확인에
  따라 이번 capability 사유와 분리. 아래는 패키지 내부 유지보수 프로그램에 대한 검토.
- 프로젝트명은 GameMaintenance.Worker이지만 실제 EXE 이름은
  Maintenance\GersangStation.GameMaintenance.exe임.
- 전용 helper 종류는 하나지만, 전체 설치 시 패키지에 포함된 7za.exe를 실행하며
  이 자식도 관리자 권한을 상속하므로 관리자 프로세스 수가 항상 하나인 것은 아님.

1. 허용 작업 및 대상 폴더 목록

사용자 기능: 게임 설치 및 경로 지정 > 설치
- 사용자가 고른 상위 폴더 아래 AKInteractive\Gersang(본섭), GerTest(테섭),
  CheonRa(천라섭)를 최종 게임 경로 G로 구성.
- 공식 전체 설치 압축 파일을 G에 내려받아 G 아래로 압축 해제.
- 압축 파일과 같은 위치의 .gsdownload, .meta 파일 사용 및 설치 후 정리.
- 취소 시 사용자가 임시 파일 삭제를 선택하면 다운로드 산출물만 정리.
- IPC worker는 UI에서 만든 AKInteractive\서버폴더 형태 자체를 강제하지 않음.
  실제 worker 허용 범위는 검증에 통과한 요청의 InstallPath임.

사용자 기능: 게임 패치 > 패치 / 다시 패치
- G 아래 게임 파일을 공식 패치 파일로 갱신.
- 임시 작업 경로: G\PatchTemp\{기준버전}-{대상버전} 및 그 하위 경로.
- 기존에 생성된 유효한 2/3클라이언트는 함께 동기화. 없는 다클라는 패치에서 생성하지 않음.
- 선택한 재다운로드 정책에 따라 해당 임시 폴더 초기화.
- 패치 성공 후 사용자가 선택한 경우 해당 임시 폴더 정리.

사용자 기능: 게임 설치 및 경로 지정 > 다클라 생성
            사이드바 실행 시 다클라 생성 확인 > 생성
- G2_CreatedByStation, G3_CreatedByStation 두 고정 형제 폴더 생성/동기화.
  예: D:\Games\Gersang2_CreatedByStation.
- 게임 파일 복사, Online 및 기타 게임 데이터 디렉터리 링크 생성/재생성.
- Assets\Config, Online 설정 파일, config.ln은 기존 사용자 설정 보존 정책 적용.
- 일반 디렉터리가 링크로 필요한 위치를 차지하면 충돌 오류로 처리.
- 게임 실행, 사용자 계정 변경, 임의 셸 명령, 레지스트리/Windows 서비스 설정은
  이 worker의 명령 종류에 포함되지 않음.

판정: 작업 종류는 Install / Patch / CreateMultiClient 세 종류로 한정됨.
대상은 상수 절대경로 allowlist가 아니라 검증한 게임 루트와 그 파생 경로임.
이 차이를 숨기지 말고 제출 자료에 명시해야 함.

2. 작업별 권한 필요성

- 심볼릭 링크 생성은 무조건 관리자 권한을 요구하지 않음.
- CreateSymbolicLink API에는 SYMBOLIC_LINK_FLAG_ALLOW_UNPRIVILEGED_CREATE가 있고,
  이 방식은 Windows 개발자 모드가 켜져 있어야 함.
- SeCreateSymbolicLinkPrivilege를 가진 사용자도 별도의 경로가 있으며,
  기본 정책에서 이 권한은 Administrators에 부여됨. 토큰에 실제 권한이 있어야 함.
- 다클라 생성은 Directory.CreateSymbolicLink를 사용하므로 링크 생성 권한이 핵심.
  파일시스템의 링크 지원 여부 확인은 링크 생성 권한 확인과 같지 않음.
- 패치는 기존 다클라가 있으면 동일한 링크 재구성 과정이 있음.
  그러나 다클라가 없는 일반 패치는 다운로드/압축 해제/파일 갱신이며,
  심볼릭 링크 때문에 반드시 권한 상승이 필요하다고 설명할 수 없음.
- 전체 설치는 다운로드와 압축 해제임. 이 로직 자체에 관리자 전용 API는 확인되지 않음.
- 현재 구현은 조건과 무관하게 세 작업 모두 requireAdministrator worker를 실행함.
  이는 현재 설계이지, 모든 세부 작업의 불가피한 운영체제 요구사항은 아님.

제출 가능 설명: 개발자 모드나 사용자 권한 정책 변경을 전제로 하지 않는 환경에서
다클라의 심볼릭 링크 생성/동기화에 필요한 권한을 사용자 승인으로 얻음.
주의: 이 설명만으로 설치와 다클라 없는 패치까지 항상 승격하는 이유는 충분하지 않음.

3. 임의 실행 방지

질문의 의미: 다른 프로그램이 이 helper를 이용해 원하는 EXE, PowerShell 명령,
cmd 명령 등을 관리자 권한으로 대신 실행시킬 수 있는지 묻는 것.

확인된 방어
- 앱은 AppContext.BaseDirectory 아래의 고정 Maintenance EXE만 실행.
- worker 시작 인수는 GUID 형식 파이프 식별자와 부모 PID 두 개만 허용.
- IPC 요청 모델에는 실행 파일명, 셸 명령, 임의 실행 인수를 전달하는 필드가 없음.
- 외부에서 전달한 URL을 worker 명령으로 실행하는 기능도 없음.
- 설치 압축 해제기는 패키지 내부 고정 후보 위치에서 찾는 7za.exe만 실행.
  실제 설치 호출은 추출기에 별도 EXE 경로를 전달하지 않음. PATH 검색 없음.
- 7za는 UseShellExecute=false로 l/x 고정 명령을 실행하며 압축 내용을 실행하지 않음.

보완 검토
- 7za 인수는 문자열 보간으로 작성됨. ArgumentList로 전달하고 경로 형식을 엄격히
  검증하면 인수 경계 보장이 더 명확해짐. 현재 임의 명령 실행을 재현한 것은 아님.
- 임의 명령 실행 기능이 없더라도 파일 경로/압축 파일 검증이 약하면
  관리자 권한 파일 쓰기 수단으로 악용될 수 있으므로 4/5번이 별도로 중요함.

4. 경로 검증 및 운영체제 위험 검토

현재 막는 것
- 패치/다클라: 절대 경로, 존재하는 디렉터리, Run.exe, Online\Map,
  Online\vsn.dat, 서버 식별 INI 존재를 확인. 다클라 생성은 버전도 읽음.
- 메인 경로의 Online\Map이 reparse point이면 다클라를 원본으로 지정한 것으로 거절.
- worker에서 다시 검사하므로 UI 검증만 믿고 쓰기 시작하지는 않음.
- 다클라 목적지는 설정에서 계산한 G2/G3_CreatedByStation과 GetFullPath 결과를 비교.
- 신규 설치는 드라이브 루트와 기존 파일 경로를 거절.
  기존 디렉터리는 비어 있거나 정해진 다운로드 산출물만 있어야 함.
  기존 설치 목적지 자체가 reparse point인 경우도 거절.
- 패치 목록의 다운로드/압축 해제 목적지가 문자열 정규화 기준 루트 밖으로 나가면 거절.
- ZIP 엔트리도 GetFullPath와 디렉터리 경계 검사를 통해 ../ 등 루트 탈출 방지.

중요한 부족분
- GetFullPath는 실제 디스크의 정션/심볼릭 링크를 따라간 최종 경로 검증이 아님.
- 메인 루트 및 모든 부모/하위 작업 경로의 reparse point를 일관되게 검사하지 않음.
  예를 들어 Online\Map 외의 목적지 디렉터리 링크나 설치 루트의 부모 정션은
  현재의 문자열 경계 검사만으로 차단한다고 보장할 수 없음.
- 검증 이후 사용 전에 경로가 다른 대상으로 교체되는 TOCTOU 방어는 확인되지 않음.
- 게임 파일명/폴더 존재 검사는 게임의 진위 확인이 아님. 구조를 흉내 낸 폴더를
  진짜 게임 설치와 암호학적으로 구분하지 않음.
- worker에는 Windows/시스템 디렉터리 거절, 로컬 일반 볼륨 한정,
  UNC/디바이스 네임스페이스 거절 등의 포괄적인 제한이 없음.
  기존 설치용 검사에는 신규 설치의 드라이브 루트 거절도 동일하게 적용되지 않음.
- 신규 설치는 존재하지 않는 임의 절대경로에 대해 true가 될 수 있음.
  부모 경로의 적합성/정션 여부와 Windows 예약 경로 등은 별도의 정책으로 제한하지 않음.
- 7za 전체 설치 경로는 앱에서 모든 엔트리를 사전 검사하지 않음.
  7za 자체 방어와 별개로 앱 수준의 경로/링크 엔트리 검증을 보장할 수 없음.
- PatchTemp 하위 재귀 삭제와 복사/덮어쓰기가 실제로 존재함.
  문자열상 게임 경로 아래라는 이유만으로 운영체제 영향이 불가능하다고 할 수 없음.
  단, 재귀 삭제가 모든 종류의 정션 대상을 무조건 따라간다고 단정하는 것도 부정확함.

판정: 보통의 잘못 지정한 폴더는 거절하지만, 관리자 경계에서 악의적으로 구성되거나
실행 중 교체된 경로까지 안전하다고 제출할 수준의 증거는 부족함. 우선 보완 대상.

5. 다운로드 출처 및 무결성 검증

현재 출처
- 패치 목록/패치 파일: GameServerHelper에 고정된 게임사 CDN HTTPS URL.
  서버 enum과 버전, 목록의 상대경로에서 주소를 구성. IPC에서 임의 URL을 받지 않음.
- 전체 설치: 게임사 CDN의 고정 서버별 7z URL.
  현재 소스의 본섭/천라섭은 HTTP, 테섭은 HTTPS.
- 사용자 설명에 따른 공식 배포 경로라는 전제이며 게임사의 도메인 소유권은 별도 검증 안 함.

현재 검사
- HTTP 상태, Content-Length, Range 응답, ETag/Last-Modified 등으로 다운로드 상태와
  이어받기 파일의 일관성을 점검. 완료 전에는 .gsdownload에 저장.
- 패치 ZIP 형식 확인 및 추출 오류, 전체 설치 7za 종료 코드로 실패를 감지.
- 패치 목록의 ZipFileCheckSum/OriginFileCheckSum/ZipCRC는 파싱하지만
  실제 적용 경로에서 내려받은 내용과 비교하는 처리는 확인되지 않음.
- ZipCrcReader 유틸리티 존재 자체는 실행 경로의 검증을 의미하지 않음.
- 공급자가 서명한 목록/해시 또는 공식 파일의 암호학적 진위 검증은 확인되지 않음.
- HTTP 리다이렉트의 최종 도메인/스킴에 대한 별도 allowlist 검사는 확인되지 않음.

실측: 2026-10-31 HEAD 요청
- 본섭 전체 설치의 동일 경로 HTTPS 주소: 200 OK. 본문 다운로드/동일성 검증 안 함.
- 천라섭 현재 경로: HTTP/HTTPS 모두 404. 현재 URL 자체 재확인 필요.

설명 방향
- 공식 파일을 직접 사용한다는 점과 앱이 자체 검증하는 범위를 정확히 구분할 것.
- 길이/ETag/CRC/압축 해제 성공은 악의적 변조 방지용 서명 검증과 같지 않음.
- 게임 런처가 나중에 검증한다는 사용자 설명은 아직 해당 EXE를 분석해 확인하지 않았음.
  설령 검증해도 관리자 추출/덮어쓰기 이후 검사이므로 worker 자체 안전성의 대체 근거는 아님.

6. IPC 인증 및 명령 검증

질문의 의미: 일반 앱이 관리자 helper에 요청할 때, 엉뚱한 프로세스가 끼어들어
파일 쓰기 명령을 보내거나 작업 내용을 바꾸지 못하는지에 대한 질문.

현재 방어
- 앱이 GUID로 이름을 만든 named pipe를 먼저 생성하고 FirstPipeInstance 사용.
- 파이프 ACL은 현재 사용자와 Administrators로 제한.
  다른 관리자 계정의 UAC 자격 증명 입력도 고려함.
- 앱은 접속한 worker의 PID가 방금 실행한 프로세스와 같은지 OS API로 검사.
- worker도 파이프 서버 PID가 인수의 부모 PID와 같은지 검사.
- 부모 프로세스 실행 경로가 동일 패키지의 GersangStation.exe인지 확인.
- 인증/요청 검증 전 게임 파일 쓰기 작업은 시작하지 않음.
- 시작 인수 형식, 작업/서버 enum, 작업별 옵션, 다클라 고정 경로를 검사.
- 메시지 길이는 최대 4MiB. 요청은 await 이전 JSON 복제로 스냅샷을 만듦.
- 한 프로세스당 최초 작업 한 개 수행 후 종료. 후속 입력은 취소 제어에 사용.
- 계정 비밀번호 등 로그인 데이터는 IPC 요청 모델에 없음.

판정 및 보완
- 기본적인 상호 프로세스 확인은 구현되어 있음. 아무 프로세스나 명령을 보내는 구조는 아님.
- 다만 명령 검증이 4번의 파일시스템 실경로 안전성을 대신하지는 않음.
- JSON의 불필요한 필드/상태별 메시지를 전부 엄격 거절하는 프로토콜은 아님.
- 실제 다른 사용자 UAC, 파이프 선점, 연결 끊김 등 공격/호환 시험은 이번에 안 함.

7. 사용자 안내

현재
- 설치는 설치 버튼 및 '선택 후 설치' 폴더 선택 후 시작.
- 설치/패치는 진행 문구에 '관리자 권한 승인 후 ... 시작'을 표시.
- 다클라 설정 페이지는 버튼과 두 목적지 경로를 표시하지만 권한 사유를 설명하지 않음.
- 사이드바의 다클라 생성 확인은 2/3클라 함께 생성/동기화 범위는 설명하지만
  관리자 권한이 필요한 이유를 별도 설명하지 않음.
- Windows UAC 자체의 승인 창은 표시됨. 앱이 UAC를 우회하는 구조는 아님.

판정: 안내가 전혀 없는 것은 아니지만, 메일의 '각 승격 전 명확한 안내'를
충분히 충족한다고 단정하기 어려움. UAC가 표시되면 진행 문구를 못 읽을 수도 있음.
권장: 승인 전 서버/작업/최종 대상 폴더/변경 내용/필요한 이유를 표시하고,
사용자가 '계속'을 선택한 뒤 승격. Dialog가 필수라는 뜻은 아니며 기존 UI에서 가능.

8. 취소 및 실패 처리

현재
- UAC 거절(error 1223)은 일반 오류와 구분하고 작업 시작 전 취소로 표시.
- UAC 대기 중 취소된 요청은 연결되어도 쓰기 요청을 보내지 않음.
- worker 연결 전 종료 및 연결 제한 시간 60초, worker 최초 연결/요청 제한 시간 30초.
- 작업 중 앱 종료/파이프 연결 끊김은 worker에 취소 전달.
- 진행/실패/취소/임시 정리 진단을 별도 메시지로 반환.
- 작업 완료/취소 후 worker 종료까지 쓰기 직렬화 gate를 유지.
- 패치는 추출 작업이 멈추기 전 취소 완료를 반환하지 않도록 기다림.
- 패치 성공 후 임시 정리 실패는 성공 유지 + 조용한 기록.
- 전체 설치의 취소 시 다운로드 산출물 유지/삭제 선택 및 정리 실패 안내 존재.

빈틈
- 취소 30초 제한이 있어도 마지막 process.WaitForExitAsync는 무기한 기다림.
  worker가 멈추면 gate와 UI도 계속 기다릴 수 있음.
- 7za 추출 프로세스에는 취소 시 Kill 처리가 있으나, 그 전에 하는 목록 조회
  TryGetTotalEntriesAsync에는 취소 시 자식 종료/종료 대기 보장이 없음.
  Process.Dispose는 자식 종료 보장이 아니므로 잔류/교착 가능성 검증이 필요.
- 동기 File.Copy/일부 디렉터리 루프는 즉시 중단 가능한 작업이 아니며
  설정 페이지의 다클라 생성에는 사용자 취소 기능 자체가 노출되지 않음.
- 전체 설치는 압축 해제 후 산출물 정리 실패를 전체 설치 실패로 반환.
  패치의 비치명적 정리 실패 정책과 다름.

9. 복구 대책

있는 것
- 실패/중단된 다운로드의 임시 파일/메타데이터를 유지하고 이어받기 또는 새 다운로드.
- 다운로드 최종 파일 전환에는 File.Move/File.Replace를 사용.
  .gsbackup은 이 다운로드 파일 전환용이지 게임 전체 백업이 아님.
- 성공한 패치 기준/대상 버전 기록과 다시 패치 기능.
- 다클라 기존 설정 보존 및 재동기화.

없는 것 / 한계
- 게임 파일 전체의 트랜잭션, 이전 버전 백업, 자동 롤백은 없음.
- 중간에 덮어쓴 파일은 실패/취소되어도 원상 복원되지 않음.
- 설치 압축 해제 도중 중단되면 일부 게임 파일이 남지만, 다음 신규 설치의
  IsInstallTargetPathAvailable은 다운로드 산출물 외 파일을 거절하므로
  같은 경로에 단순 재시도/이어설치를 할 수 없는 경우가 있음.
- 기존 vsn.dat 등이 먼저 변경된 뒤 패치가 실패하면 실제 완료 상태와
  로컬 버전 표시가 어긋날 수 있음. 직전 성공 기록만으로 모든 실패를 복구하지는 못함.
- 2클라 성공 후 3클라 실패의 부분 성공을 되돌리지 않음.

판정: 재시도/재패치 지원은 있지만 자동 원복 보장은 아님.
제출 자료에 '실패 시 모든 변경이 롤백된다'고 쓰면 안 됨.

10. 관리자 권한 없는 대안

전체 설치
- 일반 사용자가 쓸 수 있는 경로에 다운로드/압축 해제하는 작업으로 분리 가능.
- 현재는 worker가 관리자 토큰을 검사하고 종료하므로 단순 runas 제거만으로 동작하지 않음.
  비승격 작업 경로 설계가 필요하며 실제 설치 시험은 별도로 필요.

다클라 없는 패치
- 일반 사용자에게 게임 파일 수정 권한이 있고 기존 링크 경로가 안전하다면
  다운로드/추출/파일 교체는 관리자 전용 작업이 아님. 비승격 경로 분리 가능.

다클라 생성 및 기존 다클라의 패치
- 개발자 모드 또는 적절한 심볼릭 링크 사용자 권한이 있는 경우 비승격 가능성 있음.
  모든 사용자에게 개발자 모드/보안 정책 변경을 요구하는 것은 적절한 기본값이 아님.
- 권한 없는 환경에서는 링크 생성만 승격하는 더 작은 helper로 축소 가능.
- 디렉터리 정션 대안도 검토 가능하나 링크 판별/호환/삭제 정책과 실제 게임 동작 검증 필요.
- 전체 복사형 다클라는 링크 권한을 없앨 수 있지만 디스크/동기화 비용과 기존 정책이 달라짐.

결론
- '설치/패치/다클라 모두 원천적으로 관리자 권한 필수'는 사실이 아님.
- 현재 방식은 on-demand 관리자 worker로 통일한 설계이며 링크 작업이 가장 직접적인 사유.
- 현 상태를 안전성 보장이 완비된 것으로 영문화해 제출하기보다
  실경로/압축 경계, 다운로드 신뢰, 불필요한 승격, 실패 복구를 먼저 결정할 필요가 있음.

우선순위 제안 (미구현)
1) 루트/부모/하위 쓰기 경로 및 아카이브 엔트리의 실경로/링크/경계 방어.
2) 설치 다운로드 HTTPS 및 출처/무결성 정책, 천라섭 URL 재확인.
3) 설치/일반 패치 비승격 경로 또는 승격 범위를 줄이는 구조 검토.
4) 승격 전 사용자 안내 통일, worker/7za 수명 제한과 정리 보장.
5) 부분 설치 재시도 및 중단 패치 복구 정책 보강.
